# Kindle 设备边距校准

校准来源：用户的 KPW3，固件 5.16.2.1.1，霞鹜文楷 轻便版 Medium，Kindle 字号 7。实测只覆盖横向边距；分页预览的上下边距采用明确标记的估算。

| Kindle 页边距 | 无书籍 CSS 每行汉字 | 每侧设备留白校准值 |
| --- | --- | --- |
| 窄 | 16 | 80 device px |
| 中 | 14 | 137 device px |
| 宽 | 11 | 220 device px |

KPW3 屏幕为 1072×1448 px、300 ppi。按全宽汉字 1em，字号 7 校准为 55 device px/em。窄档追加 `body > * { margin-left: -0.8em !important; margin-right: -0.8em !important; }`，通过项目 vendored boko WASM 转换后，用户实机每行显示 18 字。

同一窄档改用 `-4.8%`，字号 7 下同样为 18 字；用户在更大字号下对比两本测试书：`-0.8em` 随字号放大，把正文推到贴近屏幕边框，`-4.8%` 保持稳定。因此左右边距调整改用百分比。boko 把单位写进 KFX：`$48`／`$50` 为 `{ $307: 数值, $306: 单位 }`，em 为 `$308`，百分比为 `$314`。

按 CSS 标准，`body > *` 的百分比边距相对 body 内容宽度，即屏幕宽度减去 Kindle 两侧留白（正文栏）。每侧有效留白 = 设备档位留白 + `marginX% × 正文栏宽度`（旧 em 方案为 `marginX × emPx`）；每行字数估计为 `floor((屏幕宽度 - 2 × 每侧有效留白) / emPx)`。窄档不调整为 16 字，−0.8em 或 −4.8% 为 18 字，中档 14 字，宽档 11 字。−4.8% 在中／宽档按此公式估计为 15／12 字，未经实机测量；"相对正文栏而非整屏"也只是按 CSS 标准的假设，窄档两种口径都得到 18 字，无法区分。

KO3 使用 1264px 宽度与 KPW3 的比例缩放 em 和留白，留白四舍五入到整数设备像素（窄／中／宽为 94／162／259px），其他型号暂用 KPW3 尺寸。两者均明确标为估算。其他字体、字号、书籍字体大小和缩进、自定义 CSS 不属于这组实测条件，可能改变实际字数；Kindle 自身字号设置仍然生效。

每个型号／档位在 `identity.ts` 的 `typesetting.verticalMargins` 中单独保存 `top`、`bottom` 与 `measured: false`；初始上下各采用该档位的单侧横向留白。KPW3 窄／中／宽的上下各为 80／137／220px；KO3 为 94／162／259px。`margins.ts` 的预览指标另返回 `verticalMeasured: false`，不复用横向的实测标记。页面注明「上下页边距为估算，未经实机测量」，不模拟 Kindle 页眉页脚文字，也不把这些估计写进书籍 CSS。

`ProfileSettings.deviceModel` 和 `kindleMargin` 随方案存入现有 `settings_json`，用于服务端边界校验与预览，不生成书籍 CSS。用户需在 Kindle 上选择同一档位。旧 JSON 缺少这些字段时补为 KPW3／窄，正边距值及既有 CSS 行为保留，无需数据库迁移。默认方案仍不生成 CSS；选择预览档位后可另存为自己的方案。

`ProfileSettings.marginXUnit` 为 `percent` 或 `em`。新方案默认百分比；旧 `settings_json` 没有该字段时，若已有 `marginX` 数值则按 em 读取，生成的 CSS 与之前完全一致，没有数值时按百分比。编辑器滑块始终为百分比：旧 em 方案显示原值并注明随字号缩放，滑块位置为字号 7 下的等效百分比，拖动后才改为百分比保存。

服务端不允许负边距超过校准留白：百分比 `marginX >= -设备留白 / 正文栏宽度 × 100`，em `marginX >= -设备留白 / emPx`，没有额外越屏余量。KPW3 窄／中／宽分别约为 −8.77%／−17.17%／−34.81%（em 为 −1.4545／−2.4909／−4em）；KO3 采用取整后的留白计算同一边界。上限为 40%（两侧合计仍留出正文栏）或 20em。编辑器提供 0.1% 步长，下限取当前档位的安全刻度，上限 +20%（超出的合法旧值仍显示并保留）。快捷按钮「收窄到约 1 字边距（-4.8%）」。

预览 iframe 保持设备像素尺寸并整体缩放，设备基线样式位于书籍 CSS 之前，方案 CSS 位于其后。设屏幕为 W×H，单侧设备留白为 m，上下估算为 t、b：根元素固定 W×H、无 padding、隐藏溢出；`body` 自身采用宽 `W−2m`、高 `H−t−b`、`column-width: W−2m`、`column-gap: 2m`、`column-fill: auto`，四侧 margin 为 `t m b m`。栏宽加栏间距严格等于整数屏幕宽 W，每页通过文档 scrolling element 的 `scrollLeft = (page−1) × W` 定位。

不包裹或搬动正文子节点，`body > *` 仍然直接匹配原来的块；百分比仍相对正文栏宽 `W−2m`，负百分比和旧 em 均能伸入设备留白。boko 在构建 KFX 时丢弃 html/body margin，因此基线的 margin 使用 `!important`，同时把几何属性设为 inline `!important`，防止书籍后置样式及 inline margin 覆盖设备边距；书籍的字体、行高、颜色继续参与正常级联。

页数采用 `max(1, ceil(round(原始 scrollWidth) / W))`，先清除上次末页补齐宽度再测量；整屏的精确倍数不再额外加一页。根元素的绝对定位伪元素仅把滚动范围补到最后一屏末端，不进入 body 的分栏或匹配方案选择器，避免末页偏移被浏览器夹到非整屏位置。缩短章节或重排时重新测量并夹紧页码，不把旧补齐宽度当成正文。

设备下方提供上一页／下一页和带 `aria-live` 的页码；预览聚焦时支持 ←／→／PageUp／PageDown，iframe 内同样生效。屏幕左右三分之一可点击／轻触翻页，选择文字或命中链接时不翻页。章末进入下一章第一页，章首返回上一章末页，书首／书尾禁用对应按钮；章节选择器始终回到第一页。切换页面后用 caret 或逐文本 Range 保存首个可见文字位置，CSS、档位、型号和字体变化时以该文字定位新页；字体 ready／loadingdone、设备 FontFace 和图片加载后也重新分页。无可用文本锚点时保留并夹紧页码。每行字数估计保持不变；没有把不同段落的混合行高伪装成可靠的每页行数。

无效方案保留上次有效预览样式；不向应用文档注册设备字体。SSR 首屏输出禁用的翻页控件和中性分页状态，读取 iframe、布局和字体 API 都在客户端挂载后发生，沿用现有 Solid 编译和 effect cleanup 约定。

自动回归覆盖校准公式、所有型号／档位的服务端边界、旧 JSON、新字段保存与重载、快捷按钮、生产 hydration，以及实际 WASM 转换后 KFX `$48`／`$50` 中的负值与单位（em／百分比）。分页测试覆盖整数步长、整倍数与非整倍数末页、补齐宽度清零、重排夹紧、设备 body 几何与保留的书籍样式、负边距公式、按钮／键盘／点击、章间切换、书籍边界、锚点和新控件原位 hydration。测试复用 XML DOM，并为滚动范围、caret／Range 提供合成几何；它没有 CSS 布局或级联引擎。

无浏览器环境不能确认真实多栏碎片、负边距在每栏 gutter 的绘制、根元素伪元素扩展滚动范围、字体和图片加载时的实际 Range 坐标，以及真实触摸／焦点行为。浏览器验收应使用含长段落、章标题、插图和链接的多页 EPUB：逐页确认没有相邻栏露出、末页有正文、回翻跨章正确；分别用 −4.8% 和 −0.8em 检查 gutter，给 body 添加大 margin 并确认设备边距不变，再在中间页修改字号／字体／档位／型号确认首段位置保持。Node 测试不代表这些已通过，也不替代新的 Kindle 实机验证。
