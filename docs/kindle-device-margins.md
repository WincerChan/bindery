# Kindle 设备边距校准

校准来源：用户的 KPW3，固件 5.16.2.1.1，霞鹜文楷 轻便版 Medium，Kindle 字号 7。以下只覆盖横向边距；上下边距未经测量，预览沿用原行为。

| Kindle 页边距 | 无书籍 CSS 每行汉字 | 每侧设备留白校准值 |
| --- | --- | --- |
| 窄 | 16 | 80 device px |
| 中 | 14 | 137 device px |
| 宽 | 11 | 220 device px |

KPW3 屏幕为 1072×1448 px、300 ppi。按全宽汉字 1em，字号 7 校准为 55 device px/em。窄档追加 `body > * { margin-left: -0.8em !important; margin-right: -0.8em !important; }`，通过项目 vendored boko WASM 转换后，用户实机每行显示 18 字。

每侧有效留白 = 设备档位留白 + `marginX × emPx`；每行字数估计为 `floor((屏幕宽度 - 2 × 每侧有效留白) / emPx)`。窄档 0em 为 16 字，−0.8em 为 18 字，中档 0em 为 14 字，宽档 0em 为 11 字。

KO3 使用 1264px 宽度与 KPW3 的比例缩放 em 和留白，其他型号暂用 KPW3 尺寸。两者均明确标为估算。其他字体、字号、书籍字体大小和缩进、自定义 CSS 不属于这组实测条件，可能改变实际字数；Kindle 自身字号设置仍然生效。

`ProfileSettings.deviceModel` 和 `kindleMargin` 随方案存入现有 `settings_json`，用于服务端边界校验与预览，不生成书籍 CSS。用户需在 Kindle 上选择同一档位。旧 JSON 缺少这些字段时补为 KPW3／窄，正边距值及既有 CSS 行为保留，无需数据库迁移。默认方案仍不生成 CSS；选择预览档位后可另存为自己的方案。

服务端不允许负边距超过校准留白：`marginX >= -设备留白 / emPx`，没有额外越屏余量。KPW3 窄／中／宽分别约为 −1.4545／−2.4909／−4em；KO3 的缩放比例相同。编辑器提供约 −1.5…+4em、0.1em 步长；窄档安全刻度止于 −1.4em。旧方案超过 +4em 的合法正值仍显示并保留，服务端维持原 +20em 上限。

预览 iframe 保持设备像素尺寸并整体缩放，设备基线样式位于书籍 CSS 之前，方案 CSS 位于其后。根元素横向 padding 表示设备留白，正文顶层块的负边距可扩展到这部分空间；隐藏滚动条以免其占用校准宽度，仍可滚动章节。无效方案保留上次有效预览样式；不向应用文档注册设备字体。SSR 首屏保持中性，设备数据在挂载后恢复，沿用现有 Solid 编译和 effect cleanup 约定。

自动回归覆盖校准公式、所有型号／档位的服务端边界、旧 JSON、新字段保存与重载、快捷按钮、生产 hydration，以及实际 WASM 转换后的 KFX `$48`／`$50` 负边距。Node DOM 测试不验证浏览器真实布局，也不替代新的 Kindle 实机验证。
