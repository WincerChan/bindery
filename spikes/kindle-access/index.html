Kindle 浏览器 USB 访问验证

用于 Windows 桌面 Chrome / Edge + USB 大容量存储模式的 KO3、KPW3。所有步骤的结果都显示在页面上，并汇入 D 节同一个 JSON 报告。此页面无网络请求、外部依赖或构建步骤。

  1. 在仓库根目录运行任意静态文件服务器，把 spikes/kindle-access 映射到 8790 端口，然后在 Windows Chrome / Edge 打开 http://localhost:8790。
  2. 插入 KO3，选择下面的设备标签，依次运行 B1–B6 和 C。目录选择器中先尝试 Kindle 盘符的根目录，例如 E:\。
  3. 让 B6 持续运行，拔出 Kindle，等待几次检测，再插回并观察同一句柄能否恢复；期间不要重新选择目录。
  4. 先复制或下载本次报告，再关闭标签页／重启浏览器，重新打开相同地址，检查 B4 的「加载时权限」。如浏览器提供「Allow on every visit / 每次访问都允许」，第一次选择目录时选它。
  5. 换成 KPW3，重复上述流程。每次切换设备都重新选择目录；报告用会话编号区分句柄。
  6. 复制报告反馈。重启后的报告需再导出一次；页面仅持久化目录句柄，不保存报告历史。

每次选择后将句柄写入本机 IndexedDB：数据库 kindle-spike，对象仓库 handles，键 kindle。重新打开页面时先恢复句柄，立即调用 queryPermission({ mode: 'readwrite' })，不自动请求授权。

C. WebUSB（次路径）

先展示未 open() 时可获得的描述符，包括 configurations → interfaces → alternates 的 interfaceClass（大容量存储为 0x08）。每个设备有单独的 open() 按钮，若打开成功随即 close()。绝不调用 claimInterface 或数据传输方法。
